Day 3, Afternoon • Domain 5

Identity and Access Management

Identity is the new perimeter. Domain 5 asks who is asking, how sure you are, what they may do, and whether that is still true today. Most breaches involve a stolen or misused identity, so this domain is where many controls succeed or fail.

Session: Day 3, 1:00 to 5:00 Duration: ~3.5 hrs Exam Weight: 13.6% Knowledge Check: 8 Questions

Overview

Right person, right access, right time

Identity and access management covers the whole life of an identity. An account is created after the person is proofed, it authenticates with one or more factors, it receives authorization through a model the organization chose, and it is reviewed and removed when it is no longer needed. Weakness at any stage undoes the others.

This lesson covers access to assets and the AAA model, authentication strategy, federation with third parties, authorization models, the provisioning life cycle, and the authentication systems that tie it together, including Kerberos, RADIUS, TACACS+, and LDAP.

🧭 Think like a managerAccess is a business decision. The data owner approves access, the custodian implements it, and periodic reviews confirm it is still justified. When an exam answer lets IT grant access on its own judgment, look for a better one.

Access to Assets and AAA

Access control applies to more than files. The exam lists information, systems, devices, facilities, applications, services, and identities themselves. A badge reader on a server room door and a permission on a database table do the same job: they let an approved subject reach an object and keep everyone else out. Physical and logical access should be managed together, so that leaving the organization removes both the badge and the account.

The access control steps

  • Identification: the subject claims an identity, such as a username or badge number. It must be unique.
  • Authentication: the subject proves the claim with one or more factors.
  • Authorization: the system decides what the authenticated subject may do.
  • Accountability: logs tie actions to the identity, which supports auditing and nonrepudiation. Shared accounts destroy accountability.

AAA usually stands for authentication, authorization, and accounting, the services that RADIUS and TACACS+ provide. Groups and roles simplify all of it by assigning permissions to a set of people rather than one person at a time.

💡 Exam TipIdentification without authentication proves nothing, and authentication without accountability proves nothing later. If a question describes a shared administrator account, the problem is accountability.

Managing access, not just controlling it

Access is managed across its whole life, not set once at a door. Four verbs describe the job for every asset type: provision access from an approved request, control it at the point of use, review it on a schedule, and revoke it when the need ends. A contractor’s badge, VPN account, and database role all move through the same four steps, and the revoke step should remove all of them together.

Identities are assets too. User accounts, service accounts, API keys, certificates, and workload identities grant access to everything else, so attackers target them directly. Inventory them, give each an owner, protect their credentials, and monitor their use the way you would protect a server. In cloud environments, non-human identities often outnumber people and are the easiest to forget.

Authentication Strategy

An authentication strategy covers people, devices, and services. It decides how identities are registered, which factors they use, and how long a session lasts.

Factor typeExamplesWeakness
Something you know (Type 1)Password, PIN, security questionGuessed, phished, reused
Something you have (Type 2)Smart card, hardware security key, phone authenticatorLost, stolen, or SIM-swapped (for SMS codes)
Something you are (Type 3)Fingerprint, face, iris, voiceCannot be changed if compromised; error rates

Location and behavior are sometimes added as context, but multifactor authentication means factors of different types. A password and a PIN are two items from one type, so they are single-factor.

Biometric accuracy

  • False rejection rate (Type I error): a legitimate user is turned away. It frustrates users.
  • False acceptance rate (Type II error): an impostor is let in. It defeats security.
  • Crossover error rate: raising sensitivity lowers false acceptance but raises false rejection. The point where they meet compares systems; lower is better.

Sessions, proofing, and credentials

  • Session management: random session identifiers, idle and absolute timeouts, reauthentication before sensitive actions, and secure cookie flags.
  • Registration and proofing: verify the person before issuing credentials. NIST SP 800-63 separates identity assurance (IAL, how well identity was proofed), authenticator assurance (AAL, how strong the login is), and federation assurance (FAL, how assertions are protected).
  • Credential management: password vaults for users and privileged access management for administrator credentials, with rotation and check-out.
  • Single sign-on and just-in-time access: SSO means one strong login reaches many systems, which is convenient and makes that login critical. Just-in-time access grants privileges only for the task at hand.

Passwordless authentication

Passwords are the weakest link because people can be tricked into typing them anywhere. Passwordless methods remove the shared secret. With FIDO2, the standard from the FIDO Alliance, a user registers an authenticator with a site, and the authenticator creates a public and private key pair for that site alone. WebAuthn is the browser API that lets websites use it. At login the site sends a challenge, the authenticator signs it with the private key, and the site checks the signature with the public key it stored at registration.

  • Phishing resistance: the key pair is bound to the site’s origin, so a look-alike domain receives nothing it can use. Nothing reusable crosses the network, and the server stores only public keys, so a database breach leaks no passwords.
  • Biometrics as a local unlock: a fingerprint or face scan unlocks the private key on the device. The biometric template never leaves the device and is not sent to the site.
  • Platform and roaming authenticators: a platform authenticator is built into a laptop or phone (a TPM or secure enclave). A roaming authenticator is a separate hardware security key that plugs in or taps over NFC.
  • Passkeys: FIDO credentials that can sync across a user’s devices through a platform account, which makes recovery easier. Device-bound passkeys on hardware keys never leave the device and give the highest assurance.
  • Design issues: plan account recovery (a weak recovery path undoes a strong login), enroll at least two authenticators per person, and decide when synced passkeys are acceptable and when a device-bound key is required, such as for administrators.
💡 Exam TipIf a scenario describes users being phished even though they use MFA with SMS codes or push approvals, the BEST fix is phishing-resistant authentication: FIDO2 security keys or passkeys. Push fatigue and real-time phishing proxies defeat codes and prompts, not origin-bound keys.

Federation with Third Parties

Federation lets a user sign in once with their home organization and use a partner’s service. The service trusts the identity provider instead of keeping its own passwords. Deployments may be on-premises, cloud, or hybrid, where an on-premises directory synchronizes or federates with a cloud identity service.

StandardPurposeRoles and tokens
SAML 2.0Authentication and attribute exchange, mostly for enterprise web SSOThe identity provider (IdP) sends a signed XML assertion to the service provider (SP) through the user’s browser.
OAuth 2.0Delegated authorization: an app acts on a user’s behalfThe authorization server issues an access token to a client so it can call a resource server. It does not say who the user is.
OpenID ConnectAuthentication on top of OAuth 2.0The OpenID provider returns a signed JSON Web Token (ID token) to the relying party.

A typical SAML sign-in

  • The user opens the service provider’s application.
  • The SP redirects the browser to the IdP with an authentication request.
  • The user authenticates at the IdP, ideally with MFA.
  • The IdP returns a signed assertion through the browser to the SP.
  • The SP validates the signature and audience, then creates a session.
💡 Exam TipOAuth answers “what may this app do?” OpenID Connect answers “who is this user?” If a question asks which protocol authenticates users for a modern web or mobile app, choose OIDC, not plain OAuth.
4

Authorization Models

ModelWho decidesHow it works
Discretionary (DAC)The ownerThe owner grants access through ACLs. Flexible, but users can share data unwisely. Typical of file systems.
Mandatory (MAC)The system, by policyLabels on objects and clearances on subjects, plus need to know through compartments. Users cannot change labels.
Role-based (RBAC)Administrators, by job functionPermissions attach to roles, and people get roles. Fits stable organizations; can suffer role explosion.
Rule-based (RuBAC)Global rulesThe same rules apply to everyone, such as firewall rules or “no logins after 10 p.m.”
Attribute-based (ABAC)Policies over attributesCombines subject, object, action, and environment attributes. Very fine-grained and suited to zero trust.
Risk-Adaptable (RAdAC)A risk engine weighing need and riskEvaluates each request in real time against both security risk and operational need, and can grant, deny, or demand step-up authentication. In an emergency, mission need may justify access that normal policy would refuse, with extra logging.

In any model, a policy decision point evaluates the request and a policy enforcement point, such as a gateway or application, enforces the result. Keeping them separate lets one policy govern many systems.

💡 Exam TipKey phrases point to models. “Owner” means DAC. “Labels” or “clearance” means MAC. “Job function” means RBAC. “Time, location, or device” usually means ABAC.

Write the abbreviations carefully. RBAC is role-based and RuBAC is rule-based. RAdAC goes further than ABAC: ABAC applies fixed rules to attributes, while RAdAC computes a risk level from signals such as device health, location, threat intelligence, and the sensitivity of the data, then compares it to how urgently the access is needed. The decision can change from one request to the next even when the attributes look the same.

5

The Provisioning Life Cycle

  • Provisioning: create accounts from an approved request, ideally driven by HR records, with access based on role and least privilege.
  • Role definition and transition: when people change jobs, add the new role’s access and remove the old. Skipping the removal causes privilege creep.
  • Account access review: owners recertify user, system, and service accounts on a schedule. Reviews catch orphaned accounts, excess rights, and separation of duties conflicts.
  • Privilege escalation: follow the principle of least privilege (PoLP). Administrators work from a standard account and elevate only when needed, through separate privileged accounts, membership in administrator groups granted just in time, or controlled elevation such as sudo with a restricted command list. Every use is logged, alerts fire on changes to administrator group membership, and owners review who holds those rights.
  • Service accounts: no interactive login, unique per service, long random or managed credentials, an owner of record, and inclusion in reviews.
  • Deprovisioning: disable access promptly at departure, then delete after a retention period so logs still resolve to a name.
💡 Exam TipThe best control for privilege creep is a periodic access review by the data or system owner. Automation helps, but the owner’s recertification is what the exam looks for.

Authentication and Authorization Systems

These systems do more than check passwords. Kerberos tickets carry authorization data, TACACS+ authorizes individual commands, and RADIUS returns attributes such as a VLAN or session limit. Treat each one as both an authentication service and an authorization service, and protect it as a critical asset.

Kerberos

Kerberos provides single sign-on inside a realm using symmetric keys and tickets, so passwords never cross the network. The key distribution center (KDC) has two parts: the authentication service (AS) and the ticket-granting service (TGS).

  • The client authenticates to the AS and receives a ticket-granting ticket encrypted with the KDC’s key.
  • The client presents the TGT to the TGS and receives a service ticket for a specific server.
  • The client presents the service ticket to the server, which validates it without contacting the KDC.

Tickets carry timestamps and expire, so clocks must be synchronized, usually within five minutes, to block replay. The KDC is a single point of failure and a prime target. If an attacker steals the key of the KDC’s service account (krbtgt in Active Directory), they can forge TGTs, an attack known as a golden ticket. Pass-the-ticket and Kerberoasting are related attacks.

RADIUS, TACACS+, and LDAP

SystemUseNotes
RADIUSNetwork access: Wi-Fi, VPN, 802.1XUDP; combines authentication and authorization; encrypts only the password. Diameter is its successor.
TACACS+Administrator access to network devicesTCP; separates authentication, authorization, and accounting; encrypts the entire payload; supports per-command authorization.
LDAPDirectory queries and authenticationPort 389; use LDAPS (636) or StartTLS so credentials are not sent in clear text.

    🔎 In practice

    The same request can be allowed by one model and denied by another, because each model asks a different question. DAC asks what the owner wants. MAC asks whether labels and need to know permit it. RBAC asks whether the job requires it. ABAC asks whether the full context fits policy. RAdAC asks whether the risk of this request, right now, is worth the need, which is why it alone can bend in an emergency. Notice how switching to a passkey lowers the risk score and satisfies the Restricted-data policy. Real systems often layer two or more models, and access is granted only if every layer agrees.

    Faculty Teaching Segment

    IAM is where students meet the systems they already use every day. Teach it through decisions about real accounts, not lists of acronyms.

    • Signature assignment: give students an export of 30 fictional accounts with roles, departments, last login dates, and group memberships, plus an HR roster. They perform an access review, flag orphaned accounts, privilege creep, shared accounts, and separation of duties conflicts, and write a remediation memo to the data owner.
    • Rubric criteria: every exception found and classified correctly, the right owner named for each decision, least-privilege remediation, and a sustainable review schedule.
    • Lab idea: in an isolated Windows Server lab, students build an Active Directory domain, create role-based groups, apply NTFS permissions, then move a user to a new role and verify the old access is removed. Advanced students configure a free identity provider to federate with a test application using SAML or OIDC.
    • Course fit: this domain fits an operating systems, systems administration, or security fundamentals course. It supports the CAE-CD Cybersecurity Principles (CSP) and Operating Systems Concepts (OSC) Knowledge Units.
    🎓 Teaching noteProject the playground and run the challenges as a class poll: students predict each model’s decision before you change a setting. Challenge 4, the write-down rule, reliably starts the best discussion of the session.

    Scored Knowledge Check

    Test your understanding

    Select the best answer for each question, then submit for your score and the rationale for every item. Like the exam, several options may be true; choose the best one.

    Q1.A fingerprint reader at the data center door often rejects authorized staff. Which error is occurring?

    Question 1 options
    Correct: B. Rejecting legitimate users is a false rejection, a Type I error. Lowering sensitivity reduces it but raises false acceptance, the Type II error.

    Q2.Faculty use passwords with SMS codes, yet attackers keep capturing both through look-alike sign-in pages. Which change BEST stops this attack?

    Question 2 options
    Correct: D. FIDO2 and WebAuthn credentials are tied to the legitimate origin, so a look-alike page receives nothing it can replay. Passwords, codes, and security questions can all be typed into a fake page, and push approvals can be relayed or approved through fatigue.

    Q3.In a SAML single sign-on between a college and a cloud learning platform, which party creates and signs the assertion?

    Question 3 options
    Correct: A. The IdP authenticates the user and issues a signed assertion. The browser only carries it, and the service provider validates it.

    Q4.A mobile app developer wants users to sign in with their existing accounts and needs to know who each user is. Which standard BEST fits?

    Question 4 options
    Correct: C. OAuth 2.0 delegates authorization but does not identify the user. OpenID Connect adds a signed ID token for authentication and is built for modern web and mobile apps.

    Q5.Users suddenly cannot reach any Kerberos-protected service after a server’s clock drifts by 20 minutes. Why?

    Question 5 options
    Correct: C. Kerberos uses timestamps to stop replayed tickets. When clocks differ by more than the allowed skew, often five minutes, authentication fails. Time synchronization is a dependency.

    Q6.An employee who worked in payroll, then admissions, then IT still has access from all three jobs. Which control BEST prevents this?

    Question 6 options
    Correct: A. This is privilege creep. Transfer procedures should remove old access, and owner recertification catches what slips through. Authentication strength does not address excess authorization.

    Q7.During a campus emergency, a facilities manager who normally has no access to the building safety system needs it immediately. The access system weighs the urgency against the current risk of the request, grants access, and flags it for review. Which model does this describe?

    Question 7 options
    Correct: D. RAdAC computes the security risk of each request in real time and balances it against operational need, so it can allow access that normal policy would deny when the mission requires it, with extra logging. RuBAC applies the same fixed rules to everyone, MAC follows labels, and DAC follows the owner’s wishes.

    Q8.Network engineers need centralized authentication for router logins, with per-command authorization and the whole session payload encrypted. Which protocol BEST fits?

    Question 8 options
    Correct: B. TACACS+ separates authentication, authorization, and accounting, supports per-command authorization, and encrypts the entire payload. RADIUS encrypts only the password and is aimed at network access.
