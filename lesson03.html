Day 2, Late Morning and Afternoon • Domain 3

Security Architecture and Engineering

Domain 3 is where security becomes design. It covers the principles that shape a system, the formal models that prove a rule holds, the weak points of every kind of architecture, the cryptography that protects data, and the buildings that house it all. Good design prevents problems. Bolted-on controls only chase them.

Session: Day 2, 11:00 to 5:00 Duration: ~4.5 hrs Exam Weight: 12.8% Knowledge Check: 8 Questions

Overview

Build it in, not on

Domain 3 is the broadest technical domain on the exam. It asks you to think like an architect: start from requirements, apply proven principles, pick controls that fit the system, and know where each design tends to fail. It also holds most of the exam’s cryptography and all of its site and facility security.

This lesson covers secure design principles, security models, security capabilities and architecture vulnerabilities, cryptography and key management, cryptanalytic attacks, site and facility controls, and the information system life cycle. It is a long session. Pace it with the interactive and the eMates.

🧭 Think like a managerThe exam rarely asks you to configure a cipher. It asks you to choose the right control for a requirement. Read each question for the property it protects: confidentiality, integrity, availability, authenticity, or nonrepudiation. Then pick the mechanism that delivers that property.

Learning Objectives

By the end of this lesson you will be able to…

Secure Design Principles

Secure design principles are the rules of thumb architects use before any product is chosen. The exam expects you to recognize each principle in a scenario and to spot a design that breaks one.

  • Threat modeling: find threats during design, when fixes are cheapest. Lesson 1 covered STRIDE.
  • Least privilege: give each user, process, and service only the access its task needs, for only as long as it needs it.
  • Defense in depth: layer independent controls so that one failure does not expose the asset.
  • Secure defaults: ship with the safest settings turned on. Users should have to opt out of security, not opt in.
  • Fail securely: when a component fails, it should deny access rather than allow it. A firewall that crashes should block traffic, not pass it. Life safety is the exception: doors on an escape route fail open (fail safe) to protect people.
  • Separation of duties: split a sensitive task so that no single person can complete it alone.
  • Rotation of duties: move people through sensitive roles on a schedule. A successor reviews the work and finds fraud or errors a single long-term owner could hide. It also builds backup skills.
  • Two-person integrity: a critical action, such as releasing a master key or entering a vault, requires two authorized people present at the same time, each able to stop the other. Separation of duties splits a task into parts; two-person integrity requires two people for the same act.
  • Keep it simple and small: less code and fewer features mean fewer flaws and an easier review.
  • Zero trust: never trust based on network location. Verify every request explicitly using identity, device, and context, grant least privilege per session, and assume breach. NIST SP 800-207 describes the architecture: a policy decision point evaluates each request and a policy enforcement point applies the decision.
  • Privacy by design: build privacy into the system from the start, with data minimization and privacy as the default setting. Privacy-enhancing technologies put it into practice: pseudonymization and tokenization, differential privacy (adding calibrated noise to statistics), homomorphic encryption (computing on encrypted data), secure multiparty computation, and trusted execution environments.
  • Shared responsibility: in the cloud, the provider and the customer each own part of security. The split depends on the service model.
  • Secure access service edge (SASE): a cloud-delivered model that combines network functions, such as SD-WAN, with security services, such as secure web gateway, cloud access security broker, and zero trust network access.
  • Well-architected framework: a structured design review published by a cloud provider (AWS, Microsoft Azure, and Google Cloud each have one). It checks a workload against pillars such as security, reliability, operational excellence, performance, cost, and sustainability, and it turns design principles into concrete questions an architect must answer.
💡 Exam Tip“Fail secure” and “fail safe” are not the same. Fail secure protects assets by locking down. Fail safe protects people by opening up. When human life is at stake, people come first on the exam, every time.

Security Models and Evaluation

A security model describes a policy precisely enough to prove that a system enforces it. Models are tested as rules: given a subject, an object, and an action, is access allowed? The exam focuses on four models and the properties each protects.

ModelProtectsCore rules
Bell-LaPadulaConfidentialitySimple security property: no read up. Star (*) property: no write down. Strong star property: read and write only at your own level.
BibaIntegritySimple integrity property: no read down. Star (*) integrity property: no write up. Invocation property: a subject cannot invoke a subject of higher integrity.
Clark-WilsonIntegrity (commercial)Users reach constrained data items only through well-formed transformation procedures. Enforces separation of duties and auditing through the access triple: user, program, data.
Brewer-NashConflict of interestAccess depends on what a subject has already accessed. Once you see one client in a conflict class, competitors in that class are walled off.

Other models to recognize

  • State machine: the system is secure if it starts in a secure state and every transition leads to another secure state. Bell-LaPadula and Biba are built on it.
  • Information flow: controls how information moves between levels, which helps find covert channels.
  • Noninterference: actions at a higher level must not affect what a lower level can observe.
  • Take-Grant: a graph model of how rights are passed with take, grant, create, and remove operations.
  • The “Star Model”: the outline lists it beside Biba and Bell-LaPadula. Study sources differ on its meaning, and most treat it as the star (*) properties those two models share. Know both star rules well and you are covered.
💡 Exam TipBell-LaPadula and Biba are mirror images. If you remember that Bell-LaPadula protects secrets (“no read up, no write down”), flip both rules for Biba (“no read down, no write up”). The word simple always means read. The star always means write.

Selecting controls and evaluating products

Controls are selected from the system’s security requirements, not from a vendor catalog. Requirements come from the risk assessment, data classification, and laws that apply. Product assurance can be checked against Common Criteria (ISO/IEC 15408). A vendor describes the product’s security functions in a security target, often written against a protection profile, and an accredited lab evaluates it to an Evaluation Assurance Level from EAL1 (functionally tested) to EAL7 (formally verified design and tested). A higher EAL means more rigorous evaluation, not necessarily more security features.

Security Capabilities and Architecture Weak Points

Security capabilities of information systems

  • Memory protection: the operating system isolates each process’s memory, using techniques such as virtual memory and paging, protection rings, address space layout randomization, and data execution prevention.
  • Trusted Platform Module (TPM): a chip on the motherboard that stores keys, measures the boot process, and supports full-disk encryption tied to the device.
  • Hardware Security Module (HSM): a dedicated, tamper-resistant device for high-volume key generation, storage, and signing, used by certificate authorities and payment systems.
  • Encryption and decryption: built into processors (for example AES instruction sets), drives (self-encrypting drives), and platforms.

Operational technology and industrial control systems

Operational technology monitors and controls physical processes: power, water, manufacturing, and building systems such as HVAC and campus access control. Industrial control systems include SCADA systems that supervise wide areas, distributed control systems for plants, and programmable logic controllers (PLCs) that run the equipment. In OT the priorities flip. Safety and availability come first, then integrity, then confidentiality. A patch that reboots a controller can stop a production line, so systems often run for decades with long patch cycles.

  • Purdue model: a reference architecture of levels. Level 0 is the physical process (sensors and actuators), Level 1 basic control (PLCs), Level 2 supervisory control (HMI, SCADA), Level 3 site operations (historians), and Levels 4 and 5 the enterprise IT network. An industrial DMZ between Levels 3 and 4 brokers every connection between IT and OT.
  • Legacy protocols: Modbus and DNP3 were built for closed networks and often lack authentication and encryption. Anyone who can reach the network can often send commands.
  • IT and OT convergence: remote access, cloud analytics, and IoT sensors connect plants to business networks, which exposes OT to IT threats. Stuxnet showed that malware can cause physical damage.
  • Controls: ISA/IEC 62443 organizes OT security into zones and conduits with target security levels. Common controls are strict segmentation, one-way (data diode) gateways, passive network monitoring that does not disturb the process, an accurate asset inventory, and compensating controls where patching is not possible. NIST SP 800-82 gives OT security guidance.
💡 Exam TipPolyinstantiation answers inference questions. It stores more than one version of a record at different classification levels, so a low-level user sees a cover story instead of a telling gap.

Cryptography Fundamentals

Cryptography delivers four of the five pillars. Encryption gives confidentiality. Hashing gives integrity. Signatures and certificates give authenticity and nonrepudiation. Availability is the one property cryptography does not provide, and lost keys can actually take it away.

SymmetricOne shared secret key encrypts and decrypts. Fast, so it protects bulk data. The hard part is distributing keys. Examples: AES (128, 192, or 256-bit keys), ChaCha20, and legacy 3DES. n users need n(n−1)/2 keys: 10 users need 45.
AsymmetricA public and private key pair. Slower, so it protects keys and signatures rather than bulk data. Solves key distribution. Examples: RSA, Diffie-Hellman, and elliptic curve cryptography (ECC). n users need 2n keys: 10 users need 20.

Real systems are hybrid. TLS uses asymmetric cryptography to agree on a session key, then symmetric encryption for the data. ECC reaches the same strength as RSA with much shorter keys (a 256-bit ECC key is roughly equal to a 3072-bit RSA key), which suits mobile and IoT devices. Diffie-Hellman lets two parties agree on a shared secret over an open channel, but it does not authenticate them by itself, so it is vulnerable to an adversary in the middle unless the exchange is signed. Ephemeral Diffie-Hellman provides perfect forward secrecy: stealing a long-term key later does not unlock past sessions.

Block cipher modes

ModeHow it worksExam point
ECBEach block encrypted on its ownIdentical plaintext blocks give identical ciphertext, so patterns show. Avoid it.
CBCEach block is XORed with the previous ciphertext block, starting with an IVHides patterns; errors carry to the next block; no built-in integrity.
CTREncrypts a counter to create a key streamParallel and fast; never reuse a counter value with the same key.
GCMCounter mode plus an authentication tagAuthenticated encryption: confidentiality and integrity together.

Hashing and message authentication

A hash function turns any input into a fixed-length digest. It is one-way and should be collision resistant. SHA-256 and SHA-3 are current choices. MD5 and SHA-1 are broken for collision resistance. A hash alone proves integrity only if the hash itself is protected. An HMAC mixes a shared secret key into the hash, so it proves integrity and that the sender held the key. Because both parties share that key, an HMAC cannot provide nonrepudiation.

💡 Exam TipKey-length math appears often. Each added bit doubles the key space, so a 128-bit key has 2128 possible values. Moving from 56-bit DES to 128-bit AES does not make the key space about twice as large. It makes it 272 times larger.

Signatures, PKI, and Key Management

Which key does what

GoalSender usesRecipient uses
ConfidentialityRecipient’s public keyRecipient’s private key
Digital signatureSender’s private key (signs the hash)Sender’s public key (verifies)
BothSigns with own private key, then encrypts with recipient’s public keyDecrypts with own private key, then verifies with sender’s public key

Public key infrastructure

A PKI binds public keys to identities. A certificate authority (CA) signs X.509 certificates after a registration authority verifies the requester. Trust runs from an offline root CA through intermediate CAs to the end-entity certificate. Revoked certificates are published in a certificate revocation list or checked live with the Online Certificate Status Protocol (OCSP). Certificate pinning and certificate transparency logs help detect misissued certificates.

PKI also solves key distribution. Symmetric keys are not mailed around; they are wrapped with a recipient’s public key or agreed through an authenticated key exchange such as TLS. Inside an organization, a key management system or HSM distributes and wraps keys so that applications never handle raw key material.

Cryptographic life cycle and key management

  • Life cycle: generate keys with a strong random source, distribute them securely, store them protected (often in an HSM), use them only for their purpose, rotate them on schedule, and archive or destroy them when they retire. Algorithms have a life cycle too. Plan to replace them as they weaken.
  • Practices: rotate keys on a schedule and after any suspected compromise, use split knowledge and dual control for master keys, provide key escrow or recovery where policy requires it, and keep data-encryption keys separate from key-encryption keys.
  • Access management: control who and what can use each key, not just who can read it. Grant key use by role in the key management system, require approval for administrative actions, separate key administrators from key users, and log every use for review.

Post-quantum cryptography

A large quantum computer running Shor’s algorithm would break RSA, Diffie-Hellman, and elliptic curve cryptography, which covers almost all of today’s key exchange and signatures. Grover’s algorithm only halves the effective strength of symmetric keys and hashes, so AES-256 and SHA-384 remain strong. The urgent threat is harvest now, decrypt later: an adversary records encrypted traffic today and decrypts it once quantum computers are ready. Data that must stay secret for many years is already at risk.

NIST standardAlgorithmUse
FIPS 203ML-KEM (from CRYSTALS-Kyber), lattice basedKey encapsulation: establishing shared keys
FIPS 204ML-DSA (from CRYSTALS-Dilithium), lattice basedDigital signatures, the general-purpose choice
FIPS 205SLH-DSA (from SPHINCS+), hash basedDigital signatures with conservative, hash-only assumptions

Migration starts with a cryptographic inventory: find every place the organization uses public key cryptography, then rank by data lifetime and exposure. Many deployments use hybrid key exchange that combines a classical and a post-quantum algorithm, so security holds if either one survives. Crypto agility, the ability to swap algorithms through configuration instead of rewriting code, makes this transition and the next one manageable. Post-quantum cryptography runs on ordinary computers. It should not be confused with quantum key distribution, which uses quantum physics and special hardware to detect eavesdropping on a key exchange.

💡 Exam TipIf the question asks for nonrepudiation, the answer involves the sender’s private key. Only one person holds it. Symmetric keys and HMACs cannot provide nonrepudiation, because more than one party holds the secret.

Cryptanalytic Attacks

Attacks on cryptography are classified by what the attacker has to work with, or by where they strike: the math, the implementation, or the system around it.

AttackWhat the attacker has or does
Brute forceTries every possible key. Defeated by key length.
Ciphertext onlyHas only ciphertext. The hardest starting point.
Known plaintextHas some plaintext and its matching ciphertext.
Chosen ciphertextCan get chosen ciphertexts decrypted and study the results.
Frequency analysisCounts symbol frequency to break simple substitution ciphers.
ImplementationExploits flaws in how the algorithm was coded or configured, not in the math.
Side-channelMeasures timing, power, sound, or emissions to recover secrets.
Fault injectionForces errors with voltage glitches, clock changes, or heat, then analyzes the faulty output.
TimingA side-channel that infers secrets from how long operations take. Constant-time code is the defense.
Adversary in the middle (AitM)Intercepts and relays traffic between two parties, often to steal session tokens and bypass MFA. Defeated by authenticated key exchange, certificate validation, and phishing-resistant authentication.
Pass the hashReuses a captured password hash to authenticate without cracking it.
Kerberos exploitationForged or stolen tickets, such as golden and silver tickets, or offline cracking of service tickets (Kerberoasting).
RansomwareUses strong encryption against the victim. Backups and key hygiene matter more than cryptanalysis.
Zero-dayExploits a flaw the vendor does not yet know about or has not patched. No signature exists, so defenses rely on layered controls, behavior monitoring, segmentation, and fast response.

Artificial intelligence threats

Systems that use machine learning add a new attack surface: the training data, the model, and its inputs. The architect’s job is to treat the model as a component with its own threats and controls.

  • Adversarial AI and evasion: inputs crafted with small, often invisible changes that make a model misclassify, such as altered images or malware tuned to slip past an ML detector. Defenses include adversarial testing, input validation, and not relying on a single model for a security decision.
  • Model and data poisoning: corrupting training data or the model itself so it learns a hidden behavior or backdoor. Defenses include data provenance and integrity checks, controlled training pipelines, signed models, and monitoring for drift.
  • Deepfakes: synthetic audio, video, or images that impersonate real people, used for fraud and social engineering, such as a cloned executive voice approving a wire transfer. Defenses are process controls: out-of-band verification, callback procedures, and dual approval for payments.
  • Prompt injection and model theft: instructions hidden in input that redirect a language model, and repeated queries that extract a model or its training data. Limit what the model can access and do, and filter its inputs and outputs.
💡 Exam TipSalting defeats precomputed rainbow tables, because each password hash uses a unique random value. Key stretching (bcrypt, scrypt, PBKDF2, Argon2) slows every guess. Use both for stored passwords.

Site, Facility, and the System Life Cycle

Physical security begins with the site. Crime Prevention Through Environmental Design (CPTED) uses natural surveillance, natural access control, and territorial reinforcement so the layout itself discourages intruders. Sensitive rooms belong in the center of the building, away from exterior walls, top floors, and basements that flood.

  • Wiring closets and intermediate distribution frames: locked, monitored, and never shared with janitorial storage.
  • Server rooms and data centers: layered access control, no windows, raised floors or overhead cabling, hot and cold aisles, and monitoring for temperature and humidity.
  • Media storage and evidence storage: restricted access with logs. Evidence storage must preserve the chain of custody.
  • Restricted and work areas: badges, mantraps, escorts for visitors, and clean desk policies.
  • Utilities and HVAC: positive pressurization keeps contaminants out. ASHRAE guidance recommends about 18 to 27 °C (64 to 81 °F). Too dry causes static, and too humid causes corrosion.
  • Power: know the terms. A blackout is total loss. A fault is a momentary loss. A brownout is prolonged low voltage, and a sag is a momentary one. A surge is prolonged high voltage, and a spike is a momentary one. A UPS bridges short outages. A generator covers long ones. Redundant feeds from separate substations add resilience.

Fire prevention, detection, and suppression

U.S. classFuelSuppression
ACommon combustibles: paper, woodWater, foam
BFlammable liquids and gasesCO2, foam, dry chemical
CEnergized electrical equipmentCO2, clean agent gas (such as FM-200), dry chemical
DCombustible metalsDry powder
KCooking oils and fatsWet chemical

Water sprinkler systems come in four types. Wet pipe holds water in the pipes at all times. Dry pipe holds air until a head opens, which suits freezing areas. Deluge opens every head at once for high-hazard areas. Pre-action fills the pipes only after detection and then waits for a head to melt, which gives staff time to respond. Pre-action is the usual choice for data centers. Halon is no longer produced because it depletes ozone. Clean agents such as FM-200, Novec 1230, and inert gas blends have replaced it. Carbon dioxide is dangerous to people in occupied rooms.

Managing the information system life cycle

Security belongs in every stage of the system life cycle, which ISO/IEC/IEEE 15288 and NIST SP 800-160 describe: stakeholder needs and requirements, requirements analysis, secure architectural design, development and implementation, integration, verification and validation, continuous security review, transition and deployment, operations and maintenance, and retirement with secure disposal. Each stage has a security task. Requirements capture security needs, secure architectural design applies the principles in this lesson, verification tests them, operations monitor them, and secure disposal sanitizes media and revokes credentials and keys.

Continuous security review means security is not checked once at a gate and forgotten. Designs, configurations, and threat models are revisited whenever the system, its threats, or its dependencies change, and at a regular interval in between. Automated configuration checks and periodic architecture reviews keep the system aligned with its security requirements over its whole life.

Faculty Teaching Segment

Domain 3 is the hardest domain to teach in a single course because it spans hardware, math, and buildings. Anchor it in two ideas: every design decision protects a property, and every mechanism has a place where it breaks.

  • Signature assignment: give students a short requirements brief, such as a clinic that must share records with labs. Each student selects the encryption, hashing, signature, and key management approach, names the property each one protects, and justifies the choice in one page.
  • Rubric criteria: each control matched to the right property, the correct key used in each step, a realistic key management plan, and one named weakness with its mitigation.
  • Lab idea: students use the Model Rule Tester above, then write three original scenarios of their own for classmates to solve. A second lab hashes a file, changes one character, and compares the digests, which makes the avalanche effect visible.
  • Course fit: this domain maps to a cryptography, secure systems, or security architecture course. It supports the CAE-CD Basic Cryptography (BCY), Advanced Cryptography (ACR), and Cybersecurity Principles (CSP) Knowledge Units.
🎓 Teaching noteTeach Bell-LaPadula and Biba together and draw only arrows. Students who memorize slogans mix them up under pressure. Students who see where information flows can rebuild both models from scratch.

Scored Knowledge Check

Test your understanding

Select the best answer for each question, then submit for your score and the rationale for every item. Like the exam, several options may be true; choose the best one.

Q1.A research group of 50 people wants every pair of members to communicate privately using symmetric encryption only. How many keys are needed?

Question 1 options
Correct: B. Symmetric keys for n users: n(n−1)/2 = 50 × 49 / 2 = 1,225. Option A (2n) is the asymmetric count, and option C forgets to divide by two.

Q2.Under Bell-LaPadula, a user cleared for Secret tries to copy text into an Unclassified document. Which rule denies the action?

Question 2 options
Correct: D. Writing to a lower level is a write down, which the Bell-LaPadula star property forbids. The simple security property governs reads. Options B and C belong to Biba.

Q3.A financial system lets clerks change account balances only through approved programs that log every change, and no clerk can both enter and approve a transfer. Which model does this BEST describe?

Question 3 options
Correct: A. Clark-Wilson protects commercial integrity with well-formed transactions (approved programs), separation of duties, and auditing. Bell-LaPadula protects confidentiality, Brewer-Nash prevents conflicts of interest, and Take-Grant models how rights are passed.

Q4.A dean wants proof that a policy memo came from the provost and was not altered. Which key does the provost use to create that proof?

Question 4 options
Correct: C. A digital signature is created with the sender’s private key and verified with the sender’s public key. That provides integrity, authenticity, and nonrepudiation. The dean’s public key would provide confidentiality, not proof of origin.

Q5.An application must encrypt records with AES and also detect any change to the ciphertext. Which mode BEST meets both needs?

Question 5 options
Correct: C. Galois/Counter Mode is authenticated encryption. It adds an authentication tag, so it provides confidentiality and integrity together. ECB, CBC, and CTR provide confidentiality only and need a separate MAC for integrity.

Q6.A user with access only to unclassified shipping records notices that deliveries to one base suddenly tripled, and correctly concludes that a classified deployment is underway. What is this called?

Question 6 options
Correct: A. Inference is deducing sensitive information from data you are allowed to see. Polyinstantiation is a defense against it, not the attack itself.

Q7.A university research office stores grant data that must stay confidential for 20 years. Its VPN uses RSA key exchange. Why should the office plan its post-quantum migration NOW rather than wait for large quantum computers?

Question 7 options
Correct: D. This is harvest now, decrypt later. Data with a long secrecy requirement is exposed today if its key exchange will fall to Shor’s algorithm. Grover’s algorithm only halves symmetric strength, so AES-256 stays strong. Post-quantum algorithms run on ordinary computers, and quantum key distribution is a separate technology.

Q8.A college’s machine learning model flags fraudulent financial aid applications. An insider slips hundreds of mislabeled records into the next training set so that one pattern of fraud is classified as legitimate. Which threat is this, and what is the BEST control?

Question 8 options
Correct: B. Corrupting training data to plant a hidden behavior is data poisoning. The fix protects the pipeline: verified data sources, integrity checks, controlled access to training data, and review of model behavior before release. Evasion manipulates inputs at prediction time, not training data.
